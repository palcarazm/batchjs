# Migrating to v2.0

Version 2.0 introduces a major architectural change: the new `Runnable` base class with a unified state machine and typed event system. This guide helps you migrate your existing code.

## Breaking Changes Summary

### Event Names Changed

| Old Event         | New Event         | Payload Change                                                               |
|-------------------|-------------------|------------------------------------------------------------------------------|
| `start`           | `started`         | `void` → `{ name: string }`                                                  |
| `end`             | `completed`       | `void` → `{ name: string }`                                                  |
| `error`           | `failed`          | `Error` → `{ name: string; error: Error }`                                   |
| `stepStart`       | `step-started`    | `Step` → `{ step: Step }`                                                    |
| `stepEnd`         | `step-completed`  | `Step` → `{ step: Step }`                                                    |
| `stepError`       | `step-failed`     | `{ step, error }` → `{ step: Step; error: Error; rollback: RollbackStatus }` |
| `step-cancelled`  | `step-cancelled`  | `Step` → `{ step: Step; rollback: RollbackStatus }`                          |
| (new)             | `step-finished`   | N/A  → `{step: Step; status: RunnableStatus; rollback: RollbackStatus }`     |

### New Events

| Event                 | Payload                                                     | Description                          |
|-----------------------|-------------------------------------------------------------|--------------------------------------|
| `rollback-succeed`    | `void`                                                      | Step rollback succeeded              |
| `rollback-failed`     | `{ error: Error }`                                          | Step rollback failed                 |
| `step-rollback-succeed` | `{ step: Step }`                                            | Job re-emits step rollback success   |
| `step-rollback-failed`  | `{ step: Step; error: Error }`                              | Job re-emits step rollback failure   |

### `Job.run()` No Longer Returns a Promise

**Before:**

```typescript
await job.run(); // Resolves when job completes
```

**After:**

```typescript
job.run(); // Returns immediately

// Listen to finished event for completion
job.on('finished', ({ status }) => {
  if (status === RunnableStatus.COMPLETED) {
    console.log('Job completed');
  } else {
    console.log('Job failed or cancelled');
  }
});
```

## Migration Steps

### 1. Update Event Listeners

**Before:**

```typescript
job.on('start', () => console.log('Started'));
job.on('end', () => console.log('Ended'));
job.on('error', (error) => console.error(error));
job.on('stepStart', (step) => console.log(`Step ${step.name} started`));
job.on('stepEnd', (step) => console.log(`Step ${step.name} ended`));
job.on('stepError', ({ step, error }) => console.error(`Step ${step.name} failed`, error));
job.on('step-cancelled', (step) => console.log(`Step ${step.name} cancelled`));
```

**After:**

```typescript
job.on('started', ({ name }) => console.log(`Job ${name} started`));
job.on('completed', ({ name }) => console.log(`Job ${name} completed`));
job.on('failed', ({ name, error }) => console.error(`Job ${name} failed`, error));
job.on('step-started', ({ step }) => console.log(`Step ${step.name} started`));
job.on('step-completed', ({ step }) => console.log(`Step ${step.name} completed`));
job.on('step-failed', ({ step, error, rollback }) => 
  console.log(`Step ${step.name} failed with rollback: ${rollback}`)
);
job.on('step-cancelled', ({ step, rollback }) => 
  console.log(`Step ${step.name} cancelled with rollback: ${rollback}`)
);
job.on('step-finished', ({ step, status, rollback }) => 
  console.log(`Step ${step.name} finished with ${status} (rollback: ${rollback})`)
);
job.on('step-rollback-succeed', ({ step }) => 
  console.log(`Step ${step.name} rollback succeeded`)
);
job.on('step-rollback-failed', ({ step, error }) => 
  console.log(`Step ${step.name} rollback failed: ${error.message}`)
);
```

### 2. Update `run()` Usage

**Before:**

```typescript
try {
  await job.run();
  console.log('Job completed');
} catch (error) {
  console.error('Job failed', error);
}
```

**After:**

```typescript
job.run();

job.on('finished', ({ status }) => {
  if (status === RunnableStatus.COMPLETED) {
    console.log('Job completed');
  } else if (status === RunnableStatus.FAILED) {
    console.log('Job failed');
  } else if (status === RunnableStatus.CANCELLED) {
    console.log('Job cancelled');
  }
});

// For error details, listen to failed event
job.on('failed', ({ error }) => console.error('Job failed with:', error));
```

## New Features to Explore

- **`finished` event**: Know when any job/step reaches a terminal state.
- **`transition-cancelled` event**: Know when a lifecycle hook cancels a transition.
- **`transition-invalid` event**: Know when an invalid state transition is attempted.
- **Convenience getters**: `isCreated`, `isRunning`, `isCompleted`, `isFailed`, `isCancelled`.
- **`Runnable.id`** – All runnables (Job, Step) now have a deterministic UUID v5 identifier based on their name and parameters.
- **Fully typed events**: Autocompletion for all event names and payloads in your IDE.
- **Extendable events**: Add custom events to `Job` or `Step` without conflicting with base events.
- **Cancelling jobs and steps**: Now `Job` and `Step` can be cancelled by calling `.cancel()` method.
- **Checkpointing** – Long-running jobs can now resume from failures using the new `CheckpointStore` interface. See the [Checkpointing guide](../checkpointing.md) for details.
- **Rollback** – Steps can now implement `_rollback()` to clean up side effects when they fail or are cancelled. See the [Steps guide](../steps.md#rollback) for details.
